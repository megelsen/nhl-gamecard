## Overview

Flask app that renders a single-page "gamecard" dashboard for an NHL team (standings, leaders, goalies, next opponent comparison, previous games, records vs. every opponent, playoff race). Data comes from the public NHL APIs (`api-web.nhle.com/v1/...` and `api.nhle.com/stats/rest/...`). Self-hosted on a home server with Docker Compose and served at `https://hockey.megelsen.com` through a Cloudflare Tunnel (see Self-hosting below). It used to run on Render; that service and its keep-alive workflow are retired.

## Commands

```bash
pip install -r requirements.txt
python app.py                       # dev server on $PORT (default 8080)
gunicorn -b :8080 app:app           # production entrypoint (matches Dockerfile)
RUN_SCHEDULER=false python app.py   # skip the APScheduler + startup cache warm-up
```

There are no tests, linter, or build step. Verify changes by loading `/<TEAM_ABBR>` (e.g. `/NYR`) in a browser, or with `app.test_client()` and `RUN_SCHEDULER=false`. Run from a scratch directory if you don't want to touch the project's `cache/` (it's relative to the CWD). A cold cache takes ~25s per team page because every leader and goalie needs a separate player-landing request.

For visual checks, run the app on a spare port and screenshot with headless Chrome (`--headless=new --screenshot --virtual-time-budget=6000`). To test an interaction, save the page HTML into `static/` with an injected script that clicks the controls, serve it from the app, and delete it afterwards. That copy keeps the team colors, since they're in the stylesheet URLs. Headless Chrome won't lay out narrower than ~500px, so for phone widths wrap the page in a 375px `<iframe>` served from `static/`. Or point the iframe at `/<TEAM>` itself. Compile with `py -3.11 -W error -m py_compile ...` before finishing: production is 3.11, and the local 3.14 accepts syntax 3.11 rejects (e.g. backslashes inside f-string expressions).

Useful routes: `/player/<id>/card` (player card HTML fragment), `/player/<id>/compare.json`, `/team/<abbr>/roster.json` and `/players/ranking.json` (player comparison), `/img-proxy?url=` (assets.nhle.com images for the PNG export), `/refresh` (force-refresh the cache in a background thread; returns 404 unless the request has an `X-Refresh-Token` header matching `REFRESH_TOKEN`), `/debug-nhl?url=...` (proxy an `https://*.nhle.com` URL and show status/headers/body preview; returns 404 unless `DEBUG_ROUTES=true`), `/health`. Unknown team codes return 404; lowercase codes redirect to uppercase. Both gated routes are gated because the site is public and every call hits the NHL API from the host's IP.

Self-hosting: `compose.yml` runs the app and a `cloudflared` tunnel connector on the host (`docker compose up -d --build`, env from `.env`, see `.env.example`), both only on an isolated `public` network. The public hostname `hockey.megelsen.com` → `http://nhl-gamecard:8000` is configured in the Cloudflare dashboard, which also blocks `/refresh` and `/debug-nhl` at the edge and caches pages for 60 s. `deploy/` has the host firewall rules that keep that network off the LAN.

## Architecture

**Request flow** — `app.py:team_page` does everything for one request: fetches schedule, season, standings, team stats, team summary, playoff series and the next opponent's stats; passes them through helper functions in `modules/`; and renders `templates/index.html` with a large `vars` dict. Most "element" helpers return **pre-built HTML strings** (or pandas `DataFrame.to_html`) that the template injects with `|safe`, so markup lives partly in Python (`modules/elements/*.py`) and partly in Jinja (`templates/index.html`, `templates/macros/`).

**Module layout** — `modules/__init__.py` and `modules/elements/__init__.py` re-export every submodule's `__all__`, and `app.py` does `from modules import *`. When adding a public function, add it to that submodule's `__all__` or it won't be visible in `app.py`.
- `modules/fetch_nhl_api.py` — all NHL API calls.
- `modules/read_schedule.py` — season ID/date math and turning a schedule into `games_by_date` / `games_by_opponent`.
- `modules/fetch_team_info.py` — team info from standings, team colors from `modules/nhl_team_colors.json`.
- `modules/elements/` — one file per dashboard section, producing HTML.
- `modules/fetch_team_colors.py` — standalone scraper (runs on import, needs `bs4`) that regenerates `nhl_team_colors.json`; not part of the app.

**Caching** — Every fetch goes through `_safe_get_json(url, cache_name, force)`: today's cache → fetch (3 attempts with exponential backoff and jitter for network errors/5xx/429, none for other 4xx; `Retry-After` is honored up to 5s for page requests and 30s for forced refreshes, longer means give up) → newest older cache file (`load_latest_cache`) → `None`. After a failed fetch, the URL is skipped for 5 minutes (stale data or `None` is returned immediately) so an outage doesn't stall every request. Cache files live in `cache/<name>_<YYYY-MM-DD>.json` (`cache_utils.py`), so "fresh" means "from today"; `prune_cache` removes files older than 3 days. `_safe_get_json(..., parse=fn)` handles non-JSON bodies (CSV) the same way. Callers must handle `None`; `team_page` returns a 503 only when core data (schedule, season, standings, team stats) is missing and degrades the opponent/playoff sections otherwise. `scheduler.py` force-refreshes through the same fetch functions (so keys always match) at 06:00 and 12:00 UTC, and in a background thread at startup if there's no cache for today; a lock prevents overlapping refreshes. It pauses 0.5s between requests (~3 min for all ~100) and logs how many entries were actually updated, using `track_fetch_failures()`. `save_cache` writes atomically (temp file + rename). `modules/cache.py` / `cached_data.pkl` is an unused legacy pickle cache.

**Dynamic CSS** — Routes like `/body.css` and `/cards.css` render `templates/dynamic/styles/*.css.jinja` from the `LAYOUT` constants in `app.py`. The only team-dependent value, the primary color, comes in the URL (`/body.css?color=0038a8`, `/team_dropdown.css?color=...`, validated as 6 hex digits, else `DEFAULT_COLORS`); `index.html` links them that way. The app uses no Flask session and sets no cookies, so every response can be edge-cached by URL. Don't reintroduce per-visitor state into pages or CSS. Static CSS/JS lives in `static/styles` and `static/js`, always linked through `url_for('static', ...)`: the `static_version` hook in `app.py` appends `?v=<content hash>`, because Cloudflare makes browsers keep static files for hours and a deploy would otherwise serve stale JS. The JS handles timezone formatting, modals, the team dropdown, spoiler hiding and width syncing.

**Season phase** — `season_data['currentDate']` is the latest date with standings: it trails today by a day during the season, so don't compare it to today to detect the post-season. Standings are requested for `min(today, currentDate)` (the scheduler warms the same date). Post-season means the playoff team summary (`get_team_summary(season, 1)`) has rows; `get_special_teams_for` uses a team's playoff stats if it has any, else regular season. Team rows from the stats API are matched to standings by exact full name (`teamFullName` == standings `teamName.default`).

**Summary circles** — `templates/index.html` reads `Conf Rank` / `Conf Name` / `Conf Rank Pct` from `team_summary()` and `PP%` / `PK%` / `* Rank` / `* Rank Pct` from `get_special_teams()`. Keep those keys when changing either function.

**Standings card** — `build_standings_tables()` (`modules/elements/playoffs_race.py`) pre-renders one conference table per conference as hand-built HTML (row classes `own-team`, `cut-line`); `static/js/standingsToggle.js` only toggles `hidden`. Conferences are ordered West, then East (`CONFERENCES`), like on a map, for tabs and the playoff card alike. Use `.standings-tab`, not `.tab`, for tabs outside the topscorer modal: `topscorers_modal.js` binds every `.tab` on the page.

**Roster modal** — `build_roster_tables()` (`modules/elements/roster.py`) merges `/v1/roster/{team}/current` (all rostered players plus bio) with `club-stats` (only players who have played). Within each position tab it splits players into Lineup / Rotation / Extras, based on who dressed in the last 5 completed games (from boxscores, `get_boxscore`). Headshots carry `data-player-id` for the player cards (step 7). Use `window.addEventListener("click", ...)`, never `window.onclick =`, for outside-click closing: each modal script used to overwrite the others' handler.

**Comparisons** — Top scorers, Goalies and Last meeting all render through one JS component, `renderComparison()` in `static/js/comparison.js`. Python only supplies raw numbers: `modules/elements/compare.py` builds `{left, right, rows: [{key, left, right}]}` and `compare_mount()` embeds it as `data-compare` JSON. The goalie carousel builds the same data in JS. `COMPARE_SPECS` in `comparison.js` is the single place for labels, number formats (61%, .927, 19:06), lower-is-better stats, and amplified bars for rate stats (`spread`). To add a stat row, add its key there and supply the value from Python. In Top scorers and Goalies the top of the photo lines up with the team tags above the stat rows, with `.headshot-caption` (name, number, Show Top 5 / goalie arrows) underneath. The team tags link to that team's page (`/<TEAM>`). Colors come from `window.compareColors` (team primary; the opponent's color via `pick_contrasting_color`). Advanced rows come from NHL EDGE (`get_skater_edge` / `get_goalie_edge`): shot speed and skating speed for skaters, high-danger save % for goalies. EDGE also has high-danger shots/goals, but the user removed those rows. Expected goals (xG) isn't available from any NHL endpoint; it comes from MoneyPuck (`modules/fetch_moneypuck.py`: one season CSV for the whole league, same `playerId`s, parsed and cached as JSON, refreshed by the scheduler). Top scorers show GP, G, A, P, 5v5 on-ice xGF/60 (`skater_xg_stats`), speed and TOI, in that order; the user dropped xGA/60 and shot speed there to keep the card short (both remain in the player comparison). MoneyPuck data is free for non-commercial use only with visible credit: keep the footer credit and the card's source line.

**Playoff card** — `build_playoff_picture()` (`playoffs_race.py`) shows only the current round. Until `/v1/playoff-bracket/{year}` (year = the season's end year) has series, it projects round 1 from standings: the better division winner plays WC2, the other WC1, and 2nd plays 3rd in each division. During the playoffs it shows the lowest round with an unfinished series; after the Final, the Final. Seeds use standings labels (M1, WC2). Each series is a stacked bracket box (`series_box`), and `bracket()` pairs consecutive series, whose winners meet next round, with CSS connector lines. Keep the series order when changing how matchups are built. There's no subtitle (only a note when the card is empty); during the playoffs the round is in the title. Conference labels are vertical on the bracket's outer side (West left, East right; both left when stacked). Both conferences show at once in `.playoff-conferences`, a grid that puts them side by side when there's room and stacks them on phones. In the widest (3-column) layout the card spans two columns with the brackets flanking its middle, and the League leaders card takes the third (`standings.css`). With 2 columns (`media_scaling.css.jinja`) League leaders moves up next to Record vs (opposite conference) and the playoff card spans both columns below it (`order: 1`). With 1 column it's a normal card before League leaders. The leaders list is capped at 380px so it doesn't stretch in wide cards. Side by side, the East bracket (`bracket(..., mirrored=True)`) has its connector lines on the left so both open towards the middle (a container query on `.playoff-conferences`).

**League leaders** — `build_league_leaders()` (`modules/elements/league_leaders.py`) pre-renders lists from `/v1/skater-stats-leaders/current` and `/v1/goalie-stats-leaders/current` (`get_skater_leaders` / `get_goalie_leaders`, `limit=15`, refreshed by the scheduler). The card shows Goals / Assists / Points tabs with 5 rows each, because 5 fit the playoff card's height and 10 don't. "More stats" opens a modal with every skater and goalie category, top 15 each, opening on +/-, plus an Advanced row (each group name on its own line above its buttons): EDGE top 10s for speed, hardest shot, distance and high-danger shots on goal (`get_edge_skater_leaders`, `EDGE_LEADER_PATHS`; EDGE has no deeper lists and none for goalies; values in `.unit-value` spans), and MoneyPuck 5v5 xGF/60, xGA/60 (lowest first; both only players with `QUALIFY_SHARE` of the most games) and goalie GSAx. MoneyPuck has no sweater numbers or headshots, so they come from the cached team rosters, read cache-only (`load_latest_cache`) so the page never fetches 15 rosters itself (that got rate limited). The MoneyPuck cache files are `moneypuck_*_v2_*` since rows gained `name`/`team`. Rows read "#12 · MIN · LW". The team logo (24px, white outline, no disc) sits on the headshot's lower-right edge. Each row has a stripe on the left in the player's team primary color (abbreviation → full name from standings → `nhl_team_colors.json`), the own team's rows get the standings highlight, and ties share a rank. `static/js/leagueLeaders.js` toggles `hidden`; it uses `.standings-tab.leaders-tab` / `.leaders-chip`, not `.tab`.

**Player cards** — Any element with `data-player-id` opens a card. `static/js/playerCard.js` uses one delegated click listener and fetches `/player/<id>/card?v=<PLAYER_CARD_VERSION>` (a hash of the card template and `player_card.py`, set in `app.py`): Cloudflare has browsers keep the fragment for 4 hours, so without it a deploy would show stale cards. Add any new file the card HTML depends on to that hash. That route renders `templates/partials/player_card.html` from `build_player_card()` (`modules/elements/player_card.py`) using the cached player landing data, in the player's current team colors. The stats table shows the last 5 NHL regular seasons plus career. A traded player's per-team rows from the landing data are merged into one row (goalie GAA/SV% recalculated). Team abbreviations for the logos, and hits, come from the stats API report (`get_player_season_report`), because the landing data has only team names. Flags come from flagcdn.com via the `COUNTRY_ISO2` map (the API gives ISO alpha-3 codes); add codes there when a new country shows up. When adding a new headshot anywhere, give it `data-player-id`. Lean white captioned icons (`.card-icon-button`: Material Symbols icon + small caption, no button chrome) next to the modal's close cross compare or flip the card; any other click on the card flips it too (not when ending a text selection or tapping a stat label). Flip: front and back share one grid cell and the hidden face carries the `hidden` attribute (both show only while turning), so the back can never appear under the front even with a stale stylesheet. The back (headshot, team, flag) shows league percentiles from `build_percentiles()` as comparison rows (player vs. NHL average, bar split at the percentile, comparison.css classes rendered in the template). Each label ends with "· 82nd pctl", or for skaters' Goals / Assists / Points "· 6th in NHL" (rank among all skaters, `with_nhl_rank()`; the bar still splits at the percentile), each with its own definition (`PCT` / `RANK`). Skaters start with Goals / Assists / Points (league-wide skater summary, `get_skater_summary`, which also feeds the ranking), then EDGE, then 5v5 xGF/60 and xGA/60. NHL EDGE ships its own percentiles (position-based, higher = better); the others (G/A/P, xG/60, GSAx) are computed by `league_percentile()` among forwards or defensemen with at least 25% of the group's most games (xGA/60 lower-is-better, so a high percentile is still good). No percentile rows = no back and no flip icon. Compare: a picker in the same modal (NHL player search `search.d3.nhle.com`, called from the browser since it allows CORS; or a roster via `/team/<abbr>/roster.json`; skaters only vs. skaters, goalies vs. goalies; both lists sorted by `/players/ranking.json`, i.e. points, or games played for goalies, from league-wide stats reports cached daily by `get_player_ranking`). Comparison rows follow the Top scorers / Goalies card order, then the extras (`COMPARE_KEYS` in `playerCard.js`), then `renderComparison()` with `leftColor`/`rightColor` from `/player/<id>/compare.json` (`build_compare_player()`; `?against=<hex>` picks a contrasting color).

**Stat definitions** — `static/js/statInfo.js` holds `STAT_INFO` (advanced-stat definitions by key) and one floating info box on `<body>` (hover with a mouse; tap/click a label to open, tap it again or anywhere else to close, scrolling closes too; keyboard focus; Esc). A tap that only closes an open definition doesn't flip the card (`statInfoOpen()`). Any element with `data-stat-info="<key>"` gets it: `renderComparison()` adds it to labels whose `COMPARE_SPECS` key has a definition, and the card back's rows carry the key from `info()` in `player_card.py`. To explain a new stat, add its key to `STAT_INFO`.

**Viewer settings** — The footer has Timezone and Units selectors (`static/js/userSettings.js`), saved in `localStorage` and applied without reloading. Scripts read `window.userSettings` / `settingsTimeZone()` and re-render on the `settingschange` event: game times (`formatEventTime.js`), speed rows in comparisons (`unit: "speed"` in `COMPARE_SPECS`; values arrive in km/h), and `.unit-value` elements carrying `data-metric` / `data-imperial` (player card size; call `applyUnits(root)` after inserting such HTML).

**PNG export** — "Export PNG" in the footer (`static/js/exportPng.js`) captures `.content` with modern-screenshot, loaded from jsDelivr on first click. (html-to-image produced a ~14 MB SVG that Chrome wouldn't decode.) Controls are left out via `EXPORT_EXCLUDE`, and spoilers are revealed by dropping their covers. assets.nhle.com sends no CORS headers, so NHL images are swapped to the same-origin `/img-proxy?url=` (assets.nhle.com only) during the capture. The Google Fonts links need `crossorigin="anonymous"` so the fonts can be embedded. Add new controls to `EXPORT_EXCLUDE`. `.content` spans the window with the card rows centered, so during the capture the real `.content` is narrowed to the cards plus at most `EXPORT_FRAME` (24px) per side and centered with `margin: auto` (`exportWidth()`); the copy gets the same frame on top via `style.paddingTop` / `height`. Don't narrow the copy through modern-screenshot's `width`/`style` options: it freezes computed margins, so the copy isn't re-centered and the right side gets cut off. Export-only styling goes under `body.exporting` (`styling.css`), e.g. no dotted stat-label underline. The layout select next to the button (`#export-layout`) offers "As shown" or 1/2/3 columns. Columns come from media queries on the window width, so a column export loads the page in an off-screen iframe of a width in `EXPORT_LAYOUT_WIDTHS`, copies the standings conference and goalie indexes over (`copyViewState`), and captures there with the library loaded into the iframe. The scale drops below 2× when the image would pass ~16M pixels (iOS Safari's canvas limit). Browser Print / Save as PDF has its own `@media print` block at the end of `media_scaling.css.jinja`: one column of blocks, not grids, and no scroll boxes, because browsers don't page-break grid items and clip scroll boxes at page edges.

**No next game** — In the off-season there's no upcoming opponent: `next_game`/`next_opponent` are `None`, opponent dicts are empty, and the template and `goalieCarousel.js` render blanks/dashes. Keep that path working when touching opponent features. `TEAM_LIST` lives in `scheduler.py` and `app.py` imports it.
